╔════════════════════════════════════════════════════════════════════════════════╗
║                   QUERY PROCESSING FLOW: FRONTEND → BACKEND                    ║
╚════════════════════════════════════════════════════════════════════════════════╝


PHASE 1: FRONTEND USER INTERACTION
═══════════════════════════════════════════════════════════════════════════════

   User Input (script.js)
         │
         ├─ User types: "What is lesson 2 about?"
         ├─ Clicks Send button or presses Enter
         └─ sendMessage() function triggered
              │
              ├─ Display user message in chat
              ├─ Show loading animation
              └─ Make HTTP POST request
                   │
                   └─→ POST /api/query
                       {
                         "query": "What is lesson 2 about?",
                         "session_id": null (or existing session ID)
                       }


PHASE 2: BACKEND API LAYER (app.py)
═══════════════════════════════════════════════════════════════════════════════

   FastAPI Endpoint: @app.post("/api/query")
         │
         ├─ Receive QueryRequest from frontend
         │   {query: string, session_id: string | null}
         │
         ├─ Session Management
         │   ├─ If session_id is null:
         │   │   └─ Call session_manager.create_session()
         │   │       → Returns: "session_1" (new session)
         │   └─ If session_id exists:
         │       └─ Use provided session_id
         │
         └─ Forward to RAG System
             └─ rag_system.query(query, session_id)
                 │
                 └─→ Returns: (answer_text, sources_list)


PHASE 3: RAG ORCHESTRATOR (rag_system.py)
═══════════════════════════════════════════════════════════════════════════════

   RAGSystem.query()
         │
         ├─ STEP 1: Retrieve Conversation Context
         │   ├─ Look up session_manager.get_conversation_history(session_id)
         │   └─ Returns: Previous Q&A formatted string (or None if first query)
         │
         ├─ STEP 2: Prepare Prompt
         │   └─ Wrap query: "Answer this question about course materials: {query}"
         │
         ├─ STEP 3: Call AI Generator with Tools
         │   └─ ai_generator.generate_response(
         │        query,
         │        conversation_history,
         │        tools=[CourseSearchTool definition],
         │        tool_manager
         │      )
         │
         ├─ STEP 4: Get Search Results (if tools were used)
         │   └─ tool_manager.get_last_sources()
         │       → Returns: ["Course Title - Lesson 2", ...]
         │
         ├─ STEP 5: Update Session History
         │   └─ session_manager.add_exchange(session_id, query, response)
         │
         └─ STEP 6: Return Results
             └─ (response_text, sources_list)


PHASE 4: AI GENERATOR - CLAUDE API INTEGRATION (ai_generator.py)
═══════════════════════════════════════════════════════════════════════════════

   First API Call to Claude
         │
         ├─ Build parameters:
         │   {
         │     "model": "claude-3-5-sonnet-20241022",
         │     "messages": [{"role": "user", "content": query}],
         │     "system": system_prompt + conversation_history,
         │     "tools": [search_course_content tool definition],
         │     "tool_choice": "auto"
         │   }
         │
         ├─ Claude Analyzes Query and Decides:
         │   │
         │   ├─→ DECISION: General Knowledge Question?
         │   │   Example: "What is Python?"
         │   │   Action: Answer directly from knowledge
         │   │   Result: return response.content[0].text
         │   │
         │   └─→ DECISION: Course-Specific Question?
         │       Example: "What is lesson 2 in MCP course?"
         │       Action: Use search_course_content tool
         │       Result: response.stop_reason == "tool_use"
         │
         ├─ IF Tool Use Needed: Call _handle_tool_execution()
         │   │
         │   └─ Continue to PHASE 5


PHASE 5: TOOL EXECUTION - SEARCH (search_tools.py)
═══════════════════════════════════════════════════════════════════════════════

   ToolManager.execute_tool()
         │
         ├─ Extract tool call parameters:
         │   {
         │     "query": "lesson 2 content",
         │     "course_name": "MCP",
         │     "lesson_number": 2
         │   }
         │
         └─ CourseSearchTool.execute()
             │
             ├─ Call vector_store.search()
             │   │
             │   └─→ PHASE 6
             │
             └─ Format Results with Sources
                 ├─ Create headers: "[MCP - Lesson 2]"
                 ├─ Include content excerpts
                 ├─ Extract sources for tracking
                 └─ Store sources: self.last_sources = ["MCP - Lesson 2"]
                     │
                     └─ Return formatted_results (string)


PHASE 6: VECTOR STORE - SEMANTIC SEARCH (vector_store.py)
═══════════════════════════════════════════════════════════════════════════════

   VectorStore.search(query, course_name, lesson_number)
         │
         ├─ STEP 1: Resolve Course Name (if provided)
         │   ├─ Semantic search in course_catalog collection
         │   ├─ User says "MCP" → Find exact title "Model Context Protocol Course"
         │   └─ Returns: resolved course_title
         │
         ├─ STEP 2: Build ChromaDB Filter
         │   └─ If filtering by lesson:
         │       {
         │         "$and": [
         │           {"course_title": "Model Context Protocol Course"},
         │           {"lesson_number": 2}
         │         ]
         │       }
         │
         ├─ STEP 3: Vector Similarity Search in course_content
         │   ├─ Embed query: "lesson 2 content" → vector
         │   ├─ Search in collection with embeddings
         │   ├─ Apply filters (course_title, lesson_number)
         │   └─ Return top 5 matching chunks (MAX_RESULTS)
         │
         └─ STEP 4: Package Results
             └─ SearchResults(
                  documents=["chunk1_text", "chunk2_text", ...],
                  metadata=[
                    {"course_title": "Model Context Protocol Course", "lesson_number": 2},
                    ...
                  ],
                  distances=[0.12, 0.23, ...]  # Similarity scores
                )


PHASE 7: AI GENERATOR - SECOND CALL WITH RESULTS (ai_generator.py)
═══════════════════════════════════════════════════════════════════════════════

   _handle_tool_execution() - Second Claude API Call
         │
         ├─ Build conversation with tool results:
         │   messages = [
         │     {"role": "user", "content": "original query"},
         │     {"role": "assistant", "content": [tool_use_block]},
         │     {"role": "user", "content": [
         │       {"type": "tool_result", "content": "search results"}
         │     ]}
         │   ]
         │
         ├─ Call Claude WITHOUT tools
         │   └─ Claude synthesizes search results into final answer
         │
         └─ Return final_response.content[0].text


PHASE 8: RESPONSE BACK TO FRONTEND
═══════════════════════════════════════════════════════════════════════════════

   Response Chain
         │
         ├─ RAGSystem returns: (answer_text, sources_list)
         │   └─ answer_text = "Lesson 2 covers..."
         │   └─ sources_list = ["Course Title - Lesson 2"]
         │
         ├─ FastAPI constructs QueryResponse:
         │   {
         │     "answer": "Lesson 2 covers...",
         │     "sources": ["Course Title - Lesson 2"],
         │     "session_id": "session_1"
         │   }
         │
         ├─ Frontend receives and processes response:
         │   ├─ Remove loading animation
         │   ├─ Display assistant message with markdown
         │   ├─ Show sources in collapsible section
         │   ├─ Update currentSessionId = "session_1" (for next query)
         │   └─ Enable input for next message
         │
         └─ User sees answer in chat


════════════════════════════════════════════════════════════════════════════════
                              KEY DECISION POINTS
════════════════════════════════════════════════════════════════════════════════

1. FIRST API CALL TO CLAUDE
   ├─ Is this a general knowledge question?
   │  └─ YES: Return direct answer immediately (1 API call total)
   │
   └─ Is this a course-specific question?
      └─ YES: Request tool use → Continue to tool execution (2 API calls total)


2. TOOL EXECUTION
   ├─ Find matching courses in vector store
   ├─ Search for relevant content chunks
   └─ Format results with course/lesson context


3. SECOND API CALL TO CLAUDE
   ├─ Synthesize search results
   ├─ Generate natural, conversational answer
   └─ No meta-commentary about search process


════════════════════════════════════════════════════════════════════════════════
                              SESSION MANAGEMENT
════════════════════════════════════════════════════════════════════════════════

First Query:
  Frontend: session_id = null
  ↓
  Backend creates "session_1"
  ↓
  Sends "session_1" back to frontend
  ↓
  Frontend stores currentSessionId = "session_1"

Subsequent Queries in Same Session:
  Frontend: session_id = "session_1"
  ↓
  Backend retrieves conversation history
  ↓
  Includes history in Claude system prompt
  ↓
  Maintains context across multiple exchanges

New Session:
  User clicks "New Session" button
  ↓
  Frontend sets currentSessionId = null
  ↓
  Next query creates new session_id


════════════════════════════════════════════════════════════════════════════════
                           DATA FLOW EXAMPLE
════════════════════════════════════════════════════════════════════════════════

Query: "Tell me about lesson 3 of the Introduction course"

1. Frontend sends:
   {
     "query": "Tell me about lesson 3 of the Introduction course",
     "session_id": null
   }

2. Backend creates session_1, calls RAG system

3. RAG system calls AI generator with tools

4. Claude decides: "This is course-specific" → Use tool
   Tool: search_course_content(
     query="lesson 3 content",
     course_name="Introduction",
     lesson_number=3
   )

5. Tool execution:
   - Resolve "Introduction" → "Introduction to AI"
   - Filter by lesson_number=3
   - Semantic search returns top 5 chunks
   - Format with headers

6. Claude (second call):
   Synthesizes: "Lesson 3 covers [synthesized content from search results]..."

7. Backend returns:
   {
     "answer": "Lesson 3 covers...",
     "sources": ["Introduction to AI - Lesson 3"],
     "session_id": "session_1"
   }

8. Frontend displays answer and sources


════════════════════════════════════════════════════════════════════════════════
                          EXTERNAL COMPONENTS
════════════════════════════════════════════════════════════════════════════════

Anthropic Claude API
  └─ Model: claude-3-5-sonnet-20241022
  └─ Decides when to use tools
  └─ Synthesizes search results

ChromaDB
  └─ Persistent vector database
  └─ Two collections:
     ├─ course_catalog (course metadata)
     └─ course_content (actual course chunks)

Sentence Transformers
  └─ Embedding model: all-MiniLM-L6-v2 (configurable)
  └─ Creates vectors from text for semantic search
